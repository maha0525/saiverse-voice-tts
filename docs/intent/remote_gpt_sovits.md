# Intent: 外部 GPT-SoVITS サーバーで合成する

**ステータス**: 検証待ち (実装・隔離テスト済み。レビュー修正後の実サーバーでの再生は未検証)

利用者が Voice TTS の設定で外部サーバーを選ぶと、ローカルモデルを起動せず、
そのサーバーで音声を合成する。URL が空なら従来のローカル合成を使う。
ペルソナごとの声と、ブラウザ・バックエンド・vessel に渡る音声の対応を守る。

## 入力から再生まで

addon.json の全体設定とペルソナ別 URL → worker の実効設定 → エンジン選択 →
ペルソナ ID に対応する参照音声プロファイルの確認・必要時のアップロード →
合成 HTTP 応答の WAV デコード → 既存の文ごとの連結・保存・配信。
エンジン選択とキャッシュは worker、HTTP と音声デコードはリモートエンジンが担う。
エンジンは (エンジン名, URL, タイムアウト) ごとにキャッシュする。ローカル合成の
ペルソナと外部サーバーのペルソナが交互に話しても、ローカルの子プロセスを閉じない
(閉じるとモデルの読み直しが毎回走る)。同じ URL のタイムアウトが変わったときだけ
旧エンジンを閉じて作り直す。

## 不変条件

- 本番 DB・ペルソナ・会話・世界状態にテスト入力を送らず、LLM を呼ばない。
- URL 設定時はローカル推論への暗黙の切替を行わない。
- 外部サーバーの判定は、全体共通 URL かペルソナ別の上書き URL のどちらかがあること。
  プロファイルの読み込み (profiles.py) と worker のエンジン選択で同じ判定を使う。
- profile_id は synthesize の persona_id、またはエンジン設定の profile_id / persona_id。
  ID がなければ失敗として知らせ、複数ペルソナを同じ既定 ID に混ぜない。
- **手元のペルソナ設定 (参照音声と書き起こし) が正**。サーバーにプロファイルが無いとき、
  サーバーの書き起こしが手元と違うとき、手元の参照音声がこのエンジンで最後に確認した
  ものから変わったときは、登録し直す。同じサーバーを使う他のクライアントも同じ規則で
  登録し直すので、手元で声を差し替えればサーバーの声も追従する。
- 参照音声を設定していないペルソナは、サーバーに登録済みのプロファイルを使う。
  registry.json にそのペルソナのエントリがあればそちらを優先し、registry.json の
  `_default` (見本の声) より前に置く。見本の声をペルソナの ID でサーバーに登録すると、
  他のクライアントが登録した本人の声を上書きしてしまうため。設定ファイルにだけ URL を
  書いた場合のように `_default` に落ちたときも、worker は外部サーバーへ見本の声を渡さず、
  サーバーに登録済みのプロファイルで合成する。
- 確認済みのプロファイルはエンジン内で覚え、文ごとの確認往復を省く。合成が失敗したら
  覚えた確認を捨て、次の文で確認し直す。
- 通信・HTTP・登録拒否・不正 WAV の失敗はログと RuntimeError で worker へ伝える。
- サーバーは完成 WAV を一括で返す。synthesize_stream はそれを一チャンクとして渡し、
  既存の sub_seq / finalize 処理で文ごとに連結する。サーバーの逐次推論とは表現しない。
- 外部サーバーに送る合成引数はプロファイル ID とテキストだけ。ペルソナ別のローカル推論
  パラメータ (speed など) は外部サーバーでは効かない。

## 検証

requests のモックと合成 WAV で未登録 / 登録済み / 書き起こしの変更 / 参照音声の変更 /
通信失敗を確かめる。合成人格・一時出力先で UI 実効設定 → worker → HTTP → WAV 保存まで通し、
URL 切替・タイムアウト変更・参照音声なし・上書き URL のみ・複数文の連結・ローカルとの
交互発話を確かめる。既存アドオンテストと変更 Python の ruff check を実行する。
実サーバー接続と実際の音質・再生は、この変更の隔離テストの対象外。

## 実施結果 (2026-10-12)

- 新規テスト 19 件成功。参照音声の未登録時 PUT、登録済み時のスキップ、
  明示的な health、HTTP / タイムアウト / 不正応答、ローカル選択を検証。
- UI 設定ローダ → worker → モック HTTP → WAV 保存の隔離経路を検証。
  2 文を 480 フレーム / 24kHz の WAV に連結し、別ペルソナ ID / URL の送信、
  タイムアウト変更、URL を空に戻したローカル復帰も確認。
- 全スイート 126 件中 123 件成功。変更前 HEAD の隔離コピーは
  107 件中 104 件成功で、失敗は両方とも test_regenerate.py の同じ 3 件:
  test_404_when_message_not_found / test_history_fallback_partial_body /
  test_history_fallback_when_body_missing_context。
  いずれも manager が未取得として HTTP 400 を返す既存テストの失敗。
- 変更 Python 6 ファイルの ruff check と git diff --check は成功。
- サンドボックス内では既存の偽子プロセス通信が停止したため中断し、
  全スイートはサンドボックス外で実行した。HTTP はモック、人格は合成データ、
  保存先は一時ディレクトリ。本番への書き込み・外部 LLM 呼び出しは行っていない。

## 経緯

- 2026-10-12 レビューで次を直した。
  - 上書き URL だけを設定したペルソナ (全体共通 URL は空) が、参照音声なしだと
    プロファイル不成立になり外部サーバーに届かなかった (Codex の指摘)。
  - 初版は「登録済みプロファイルを上書きしない」としていたため、手元で参照音声を
    差し替えてもサーバーの声が古いまま残った。同じサーバーを使う既存クライアントは
    書き起こしの不一致と参照音声の変更で登録し直しており、契約を揃えると言いながら
    規則が食い違っていた。手元の設定を正とする規則に揃えた。
  - エンジンのキャッシュがエンジン名だけを鍵にしていたため、ローカルと外部の
    ペルソナが交互に話すたびにローカルの子プロセスを閉じてモデルを読み直していた。
  - 外部サーバーの URL があると、参照音声の無いペルソナが registry.json の自分の
    エントリより先に「サーバー登録済み扱い」になり、registry.json の声が使われなかった。
  - 文ごとに GET /profiles を送っていた往復を、確認済みの記憶で省いた。
  - 公開リポジトリの設定画面の説明文と文書から、個人の機体名と他の連携の名前を外した。
